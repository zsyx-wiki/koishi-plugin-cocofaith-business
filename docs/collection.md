# 图鉴模块

`collection` 记录玩家曾获得的物品。记录以 `item_id` 为准，出售或消耗物品不会删除历史。

## 收录规则

默认收录天赋、道具和彩蛋，不收录容器和可打开物品。`obtainable: false` 不表示排除图鉴；需要覆盖默认分类时，通过公开接口注册规则：

```ts
const collection = context.use<CollectionApi>("collection")

context.core.lifecycle.track(collection.configure("event_medal", {
  pool: "周年限定",
  category: "道具",
}))
```

| 字段 | 用途 |
| --- | --- |
| `excluded` | 排除该物品 |
| `category` | 覆盖显示分类 |
| `pool` | 加入指定限定池 |

同一物品只能注册一条覆盖规则。资源卸载后恢复默认分类。

## 奖励

| 常规分类 | 称号 | 加成 |
| --- | --- | --- |
| SP | 虚空收藏家 | 每日祈求上限 +10，费用 -20% |
| SSS | 大收藏家 | 每日祈求上限 +5 |
| 彩蛋 | 彩蛋收藏家 | 每日祈求上限 +5 |

限定池不参与奖励。空分类不发放称号，已发放称号不会重复创建。物品下架后不再计入当前完成度，但历史记录和已获得称号保留。

## 数据一致性

图鉴监听事务提交后的 `inventory/changed`，只处理正向获得。资产事务与图鉴写入不是同一事务，因此进程在提交后异常退出时可能漏记。

用户查看图鉴或管理员执行刷新时，会从当前背包补齐记录并重新检查奖励。已经消耗且从未记录的物品无法由背包恢复。

全体刷新按 UID 游标分批处理，每个用户独立提交。失败用户会写入汇总，不会中止整批任务。

## 公开接口

| 方法 | 说明 |
| --- | --- |
| `state(uid)` | 返回历史物品 ID |
| `has(uid, item)` | 查询是否曾获得物品 |
| `progress(uid)` | 返回当前目录完成度 |
| `details(uid, limited?, page?)` | 返回分页明细 |
| `refresh(uid)` | 从背包补齐并检查奖励 |
| `configure(item, rule)` | 注册分类覆盖规则 |

发放物品仍应使用 Core 背包事务；图鉴接口不提供直接写入历史的能力。
